Card policy + nav

A card is allowed only for something the user can act on (update, consent, live alert). Data lives in rows and tables with 1px hairlines; never a card around one number. No card nesting.

Nav: 5 persistent destinations, no sub-tabs; match detail is a split-pane inspector; ⌘K searches everything.

Cost to build

Medium-high. New app shell, row/table primitives, split-pane inspector and command palette. Data hooks and all values already exist; no new endpoints.
